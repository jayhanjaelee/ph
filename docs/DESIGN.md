# ph TUI 디자인 (DESIGN.md)

> 작성: designer / 기준: [SPEC.md](../SPEC.md) 5절, 5.1절, 5.2절 / 버전: 0.1 초안
> 구현은 `coder`, 구조 검토는 `software-architect` 가 한다. 이 문서는 `src/tui/` 의 `view`, `theme`, `keymap` 의 기준이다.
> ASCII 목업은 **근사치**다. 한글은 셀 2칸이라 정렬이 어긋나 보일 수 있다. 정확한 폭은 각 절의 규칙 표가 기준이다.

## 0. 설계 원칙

1. **색만으로 상태를 구분하지 않는다.** 모든 상태는 글자(배지, 접두 기호, 라벨) 또는 `Modifier`(REVERSED, BOLD, DIM, UNDERLINED)와 함께 표시한다.
2. **터미널 기본 색을 존중한다.** 배경은 칠하지 않는다(`Color::Reset`). 선택 강조는 `REVERSED` 로 하고, 특정 fg/bg 를 강제하지 않는다. 밝은 테마와 어두운 테마 모두에서 읽힌다.
3. **렌더링은 결정적이다.** `view(&AppState, &Theme, Rect) -> 화면` 은 시간, 환경변수, 터미널 조회에 의존하지 않는다. 레이아웃은 순수 함수(`compute_layout(area, &AppState) -> Areas`)로 분리해 `TestBackend` 로 검증한다.
4. **위험한 동작은 기본값이 안전하다.** 삭제와 변경 폐기는 확인 팝업의 기본 선택이 "취소/계속 편집" 이다.
5. **화면 상태는 `AppState` 에만 있다.** 상태 메시지는 타이머가 아니라 **다음 키 입력**으로 지운다(테스트 결정성).

## 1. 모드와 화면 상태

`Mode` 는 SPEC 의 Normal / Search / Edit / Confirm 에 팝업 종류를 더해 아래처럼 나눈다 (`TagInput`, `Help`, `Notice`, `Preview` 추가는 기본값 채택, 사용자 미확인).

| Mode | 설명 | 진입 | 빠져나오기 |
|---|---|---|---|
| `Normal` | 목록 탐색 | 시작, 다른 모드 종료 | `q` 또는 `Esc` 종료 |
| `Search` | 검색어 입력 (실시간 필터) | `/` | `Enter` 확정, `Esc` 검색어 지우고 종료 |
| `Edit` | 인라인 에디터 (수정/추가) | `e`, `a` | `Ctrl+S` 저장, `Esc` 취소 |
| `Confirm` | 확인 팝업 (삭제, 변경 폐기 등) | `d`, 편집 중 `Esc` | 팝업 안의 키 |
| `TagInput` | 태그 편집 팝업 (한 줄 입력) | `t` | `Enter` 저장, `Esc` 취소 |
| `Help` | 도움말 팝업 | `?` | `Esc`, `q`, `?` |
| `Notice` | 오류/안내 팝업 (외부 에디터 검증 실패 포함) | 오류 발생 | 팝업 안의 키 |
| `Preview` | (좁은 화면 전용) 미리보기 전체 화면 | `p` | `Esc`, `p`, `q` |

팝업은 모두 **modal** 이다. 팝업이 열려 있으면 아래 화면은 입력을 받지 않는다.

## 2. 화면 레이아웃

### 2.1 전체 구조 (Normal, 80x24 기준)

```
┌ / 검색 ──────────────────────┐┌ 코드 리뷰 요청 ───────────────────────────┐
│ (검색: / 를 누르세요)         ││ id     코드-리뷰-요청                      │
└──────────────────────────────┘│ scope  [L] local                           │
┌ 목록 (3/12) ────────────────┐ │ tags   #review #rust                       │
│>[L] 코드 리뷰 요청           │ │ desc   PR 리뷰용                           │
│ [L] 릴리스 노트 초안         │ │ 수정   2026-09-30 12:00                    │
│ [G] Code Review  (shadowed)  │ │ ────────────────────────────────────────── │
│ [G] 번역 요청     #i18n      │ │ 다음 diff 를 리뷰해줘. 관점: {{focus}}     │
│                              │ │                                            │
│                              │ │                                            │
│                              │ │                                            │
│                              │ │                                            │
│                              │ │                                            │
└──────────────────────────────┘ └────────────────────────────────────────────┘
 NORMAL │ 필터:all │ 3/12 │ local: ~/work/app/.ph          ✓ 복사됨: 코드-리뷰
 j/k 이동  / 검색  Enter 복사  a 추가  e 편집  E 외부  d 삭제  s 범위  ? 도움말
```

| 영역 | 위젯 | Constraint (ratatui) |
|---|---|---|
| 전체 수직 | `Layout::vertical` | `[Min(3), Length(1), Length(1)]` = 본문, 상태바, 키 도움말 |
| 본문 수평 | `Layout::horizontal` | `[Length(list_w), Min(0)]` (미리보기 표시 시), 숨김이면 `[Min(0)]` |
| 좌측 수직 | `Layout::vertical` | `[Length(3), Min(0)]` = 검색 박스, 목록 (낮은 화면은 2.3절) |
| 검색 박스 | `Paragraph` in `Block::bordered` | - |
| 목록 | `List` + `ListState` in `Block::bordered` | 나머지 전부 |
| 미리보기 | `Paragraph` (wrap, `scroll`) in `Block::bordered` | `Min(0)` |
| 상태바 | `Paragraph` 한 줄 (`Line` 여러 `Span`) | `Length(1)` |
| 키 도움말 | `Paragraph` 한 줄 | `Length(1)` |

`list_w = clamp(area.width * 2 / 5, 30, 48)` (정수 나눗셈). 예: 폭 80 → 32, 100 → 40, 120 → 48.

### 2.2 크기별 규칙 (결정적)

`w`, `h` 는 터미널 전체 폭과 높이(셀)다. 위에서부터 **처음 맞는 규칙**을 적용한다.

| 조건 | 동작 |
|---|---|
| `w < 40` 또는 `h < 10` | 본문 대신 `터미널이 너무 작습니다 (최소 40x10, 현재 WxH)` 한 줄만 중앙에 표시. 입력은 `q`, `Esc`, `Ctrl+C` 만 처리 |
| `w >= 80` 그리고 `h >= 12` | **미리보기 표시** (기본). `p` 로 숨김/표시 토글 |
| 그 외 (`40 <= w < 80` 또는 `h < 12`) | **미리보기 숨김**. 목록이 전체 폭. `p` 를 누르면 `Preview` 모드(전체 화면 미리보기) |
| `h >= 16` | 검색 박스는 `Length(3)` (테두리 있음) |
| `h < 16` | 검색 박스는 `Length(1)` 테두리 없는 한 줄 (`/ 검색어_`) |
| `h >= 12` | 키 도움말 줄 표시 |
| `h < 12` | 키 도움말 줄 숨김 (`?` 로만 확인). 상태바는 항상 유지 |
| 팝업 | 폭 = `min(고정폭, w - 4)`, 높이 = `min(고정높이, h - 2)`. `Clear` 로 지운 뒤 그린다 |

- 미리보기 표시 여부는 **크기에서 계산된 값**과 사용자의 `p` 토글(`AppState.preview_hidden: bool`)을 함께 본다. 크기 조건이 "숨김" 이면 토글과 무관하게 숨긴다.
- 리사이즈 이벤트는 선택 항목과 스크롤 위치를 유지한다. 선택이 화면 밖이 되면 `ListState` 의 offset 을 조정한다.

### 2.3 목록 행

한 행 형식: `<배지> <제목> [<태그들>] [(shadowed)]`

```
>[L] 코드 리뷰 요청    #review #rust
 [G] Code Review       (shadowed)
```

| 요소 | 규칙 |
|---|---|
| 선택 표시 | `List::highlight_symbol(">")` + 선택 행 `Modifier::REVERSED \| BOLD`. 비선택 행은 앞에 공백 1칸 |
| 배지 | `[L]` (local), `[G]` (global). 항상 3칸 + 공백 1칸 |
| 제목 | 표시 폭(unicode width) 기준으로 자르고, 잘리면 끝에 `…`. 한글 2칸 |
| 태그 | 남는 폭이 있을 때만 `#tag` 를 muted 색으로 나열. 폭이 모자라면 태그부터 생략한다 (제목보다 나중에 표시) |
| shadowed | local 에 같은 id 가 있어 가려진 global 항목. 행 끝에 **`(shadowed)` 글자**를 붙이고 행 전체를 `DIM` 으로 표시. 폭이 모자라면 제목을 더 자르고 `(shadowed)` 는 유지 |
| 정렬 | `updated_at` 내림차순. scope 그룹 없이 한 줄로 섞는다 |
| 제목 표시 | title 을 표시한다 (id 는 미리보기에서 확인) |

목록 블록 제목: `목록 (<현재 선택 위치>/<필터 후 개수>)`. 항목이 0개면 `목록 (0)`.

### 2.4 미리보기

`Paragraph` 여러 `Line` 으로 구성. 블록 제목은 prompt title (폭 초과 시 `…`).

```
id     코드-리뷰-요청
scope  [L] local
tags   #review #rust
desc   PR 리뷰용
수정   2026-09-30 12:00
──────────────────────────
다음 diff 를 리뷰해줘. 관점: {{focus}}
```

- 헤더 5줄은 `muted` 라벨 + `fg` 값. 값이 없으면 `tags   -`, `desc   -`.
- 구분선은 `─` 를 미리보기 내부 폭만큼 반복한다.
- 본문의 `{{name}}` 은 `var` 토큰(굵게 + 밑줄)으로 표시한다. **색이 없어도 밑줄로 구분된다.**
- 시각은 파일에 저장된 RFC3339 를 `YYYY-MM-DD HH:MM` 으로 자른다 (저장된 오프셋 그대로, 현재 시각/타임존 조회 안 함 → 결정적).
- 긴 줄은 `Wrap { trim: false }`. 본문이 넘치면 스크롤: `J`/`K` 또는 `Ctrl+d`/`Ctrl+u`(반 페이지). 오른쪽 아래에 `↓ 더 있음` 표시 (넘칠 때만, muted). 선택 항목이 바뀌면 스크롤은 0 으로 초기화한다.
- 선택 항목이 없으면 블록만 그리고 안은 비운다 (빈 상태 문구는 6절).

### 2.5 상태바 (아래에서 두 번째 줄)

한 줄 `Paragraph`. 왼쪽 정보와 오른쪽 메시지를 `Line` 두 개로 나누지 않고, 폭을 계산해 사이를 공백으로 채운다.

```
 NORMAL │ 필터:all │ 3/12 │ local: ~/work/app/.ph          ✓ 복사됨: 코드-리뷰
```

| 세그먼트 | 내용 | 스타일 |
|---|---|---|
| 모드 | `NORMAL` `SEARCH` `EDIT` `CONFIRM` `TAG` `HELP` `PREVIEW` (영문 대문자 고정) | `REVERSED \| BOLD` |
| 필터 | `필터:all` / `필터:local` / `필터:global` | `fg` |
| 개수 | `<선택>/<필터 후 전체>` | `fg` |
| 저장소 | `local: <경로>` 또는 `local 없음` | 경로는 `muted`, `local 없음` 은 `warn` + 글자 그대로 |
| 메시지 | 오른쪽 정렬, 접두 기호 포함 | 6.3절 |

- 경로는 홈 디렉터리 부분을 `~` 로 줄여 표시한다(표시용 변환은 `platform::paths` 가 제공하는 값을 받아 쓴다. view 가 환경을 읽지 않는다). 폭이 모자라면 **왼쪽부터** `…` 로 자른다 (끝 디렉터리가 중요하다).
- 폭이 모자라면 생략 순서: 메시지 자르기 → 저장소 경로 자르기 → 개수 → 필터. 모드 세그먼트는 항상 표시한다.
- 메시지는 다음 키 입력에서 지운다. 단 그 키가 만드는 새 메시지가 있으면 교체한다.

### 2.6 키 도움말 줄 (맨 아래)

모드별로 다른 문구. 폭에 맞춰 뒤에서부터 항목을 생략한다 (`? 도움말` 은 마지막까지 유지).

| Mode | 문구 |
|---|---|
| Normal | `j/k 이동  / 검색  Enter 복사  a 추가  e 편집  E 외부  d 삭제  t 태그  s 범위  p 미리보기  ? 도움말  q/Esc 종료` |
| Search | `입력 필터  ↑/↓ 이동  Enter 확정  Esc 검색 해제` |
| Edit | `Tab/Shift+Tab 필드  Ctrl+S 저장  Esc 취소  Ctrl+Z 되돌리기  Ctrl+Y 다시` |
| Confirm / Notice | 팝업 하단에 표시하므로 이 줄은 `팝업의 안내 키를 누르세요` |
| TagInput | `공백/쉼표로 구분  Enter 저장  Esc 취소` |
| Help / Preview | `Esc 닫기` (Preview 는 `j/k 스크롤  Esc 뒤로`) |

## 3. 키맵

### 3.1 원칙
- vim 스타일과 방향키를 **항상 함께** 지원한다.
- 소문자 = 일반 동작, 대문자 = 그 동작의 변형/강한 버전 (`e`/`E`, `j`/`J`).
- **종료는 `q` 와 `Esc` 둘 다** Normal 에서 앱을 종료한다 (SPEC 5절). 팝업, 검색, 편집, 미리보기, 도움말 모드 안에서 `Esc` 는 그 모드만 닫는다 (편집은 변경 확인을 거친다). `q` 는 텍스트 입력 모드(Search, Edit, TagInput)에서는 문자 입력이고, 팝업(Help, Preview)에서는 닫기다.
- `Ctrl+C` 는 Normal/Search 에서 즉시 종료, Edit 에서는 `Esc` 와 같이 취급(변경 있으면 확인).
- 텍스트 입력 모드(Search, Edit, TagInput)에서는 문자 키가 모두 입력이다. 단축키는 `Ctrl+` 조합과 특수 키만 쓴다.

### 3.2 Normal

| 키 | 동작 |
|---|---|
| `j` `↓` / `k` `↑` | 다음 / 이전 항목 (끝에서 멈춤, 순환 안 함) |
| `g` `Home` / `G` `End` | 처음 / 마지막 항목 |
| `PageDown` `Ctrl+f` / `PageUp` `Ctrl+b` | 목록 한 페이지 이동 |
| `J` / `K` , `Ctrl+d` / `Ctrl+u` | 미리보기 아래 / 위 스크롤 (반 페이지) |
| `/` | 검색 모드 |
| `Enter` `y` | 선택 prompt 의 **본문**을 클립보드로 복사 (`y` 는 vim yank 별칭) |
| `s` | scope 필터 순환 all → local → global → all |
| `a` | 새 prompt (인라인 에디터, 8절) |
| `e` | 선택 항목 인라인 편집 (8절) |
| `E` | 선택 항목 외부 에디터 편집 (9절) |
| `d` | 삭제 확인 팝업 |
| `t` | 태그 편집 팝업 |
| `p` | 미리보기 표시/숨김 (좁은 화면에서는 전체 화면 미리보기) |
| `r` | 저장소 다시 읽기 |
| `?` | 도움말 |
| `q` | 종료 |
| `Esc` | 종료 (`q` 와 같다). 확정된 검색 필터를 풀려면 `/` 를 눌러 검색 모드로 들어가 `Esc` 를 누른다 |

- 목록이 비어 있으면 `e` `E` `d` `t` `Enter` `y` 는 무시하고 메시지 `선택된 prompt 가 없습니다` (`warn`, `! ` 접두)를 띄운다.
- **TUI 의 편집/삭제/태그/복사는 선택한 항목 자신의 scope 를 대상으로 한다 (기본값 채택, 사용자 미확인; SPEC 3.2절).** CLI 의 "local 우선" 해석과 달리, 화면에 보이는 그 항목을 그대로 다룬다 (shadowed global 항목도 선택하면 global 을 편집/삭제한다). 서비스 호출 시 scope 를 명시해 넘긴다.

### 3.3 Search

| 키 | 동작 |
|---|---|
| 문자 | 검색어에 입력, **입력할 때마다** 목록 필터 갱신 |
| `Backspace` / `Ctrl+w` / `Ctrl+u` | 한 글자 / 한 단어 / 전체 삭제 |
| `←` `→` `Home` `End` | 검색어 안 커서 이동 (`Ctrl+a` / `Ctrl+e` 도 동일) |
| `↑` `↓` , `Ctrl+p` `Ctrl+n` | 검색 결과 이동 (`j`/`k` 는 문자 입력) |
| `Enter` | 검색 확정. Normal 로 돌아가되 필터 유지 |
| `Esc` | 검색어를 지우고 Normal 로 |

- 검색어 전체를 `PromptService::search` 규칙(id, 제목, 설명, 태그, 본문의 대소문자 무시 부분 문자열)으로 처리한다. `#태그` 토큰 같은 특수 문법은 지원하지 않는다 (`#` 는 일반 문자). 태그로 좁히는 기능은 CLI 의 `--tag` 만 제공한다.
- 확정된 필터가 있으면 검색 박스에 `/ 검색어` 를 유지하고 테두리를 `accent` 로 표시한다.

### 3.4 Edit (인라인 에디터) — 8절 참고

| 키 | 동작 |
|---|---|
| `Tab` / `Shift+Tab` | 다음 / 이전 필드 (순환) |
| `Ctrl+S` | 저장 |
| `Esc` | 취소 (변경 있으면 확인 팝업) |
| `Ctrl+Z` / `Ctrl+Y` | undo / redo |
| `Shift+←/→/↑/↓` , `Shift+Home/End` | 선택 |
| `Ctrl+A` `Ctrl+E` | 줄 처음 / 끝 (선택 전체는 `Ctrl+Shift+A` 는 쓰지 않는다. 터미널 호환) |
| `Ctrl+C` `Ctrl+X` `Ctrl+V` | 선택 복사 / 잘라내기 / 붙여넣기 (에디터 내부 버퍼. 시스템 클립보드 연동은 붙여넣기 이벤트(bracketed paste)로 받는다) |
| `Enter` | Body 에서는 줄바꿈. Title, Tags, Description 에서는 다음 필드로 이동 |

## 4. 색상과 테마

### 4.1 토큰 (`src/tui/theme.rs`)

`Theme` 는 필드가 모두 `ratatui::style::Style` 인 구조체다. view 는 **Color 를 직접 쓰지 않고** 반드시 토큰을 통해 스타일을 얻는다.

| 토큰 (필드명) | 용도 | ANSI 16 (기본값) | truecolor (선택) | 추가 Modifier |
|---|---|---|---|---|
| `fg` | 기본 글자 | `Reset` | `Reset` | - |
| `bg` | 배경 | `Reset` (칠하지 않음) | `Reset` | - |
| `accent` | 포커스, 활성 테두리, 강조 | `Cyan` | `Rgb(0, 175, 215)` | - |
| `muted` | 보조 글자, 비활성 테두리, 라벨 | `DarkGray` | `Rgb(128, 128, 140)` | - |
| `warn` | 경고, 주의 | `Yellow` | `Rgb(215, 160, 0)` | `BOLD` |
| `error` | 오류, 삭제 | `Red` | `Rgb(215, 60, 60)` | `BOLD` |
| `ok` | 성공 메시지 | `Green` | `Rgb(60, 175, 90)` | - |
| `border` | 비활성 테두리 | `muted` 와 같음 | 같음 | - |
| `border_focus` | 활성 테두리 | `accent` 와 같음 | 같음 | `BOLD` |
| `selection` | 목록 선택 행 | 색 없음 | 색 없음 | `REVERSED \| BOLD` |
| `badge_local` | `[L]` 배지 | `Green` | `Rgb(60, 175, 90)` | `BOLD` |
| `badge_global` | `[G]` 배지 | `Blue` | `Rgb(90, 140, 240)` | `BOLD` |
| `tag` | `#tag` | `Magenta` | `Rgb(180, 110, 200)` | - |
| `var` | `{{var}}` | `Yellow` | `Rgb(215, 160, 0)` | `BOLD \| UNDERLINED` |
| `shadowed` | 가려진 항목 | 색 없음 | 색 없음 | `DIM` |
| `mode_badge` | 상태바 모드 세그먼트 | 색 없음 | 색 없음 | `REVERSED \| BOLD` |
| `popup_border` | 팝업 테두리 | `accent` | 같음 | `BOLD` |
| `popup_danger` | 삭제 팝업 테두리와 제목 | `Red` | 같음 | `BOLD` |

주의:
- `Reset` 을 fg/bg 로 쓰는 이유는 사용자 터미널 테마를 존중하기 위해서다. `Color::Black`/`Color::White` 는 쓰지 않는다 (어두운/밝은 테마 중 한쪽에서 안 보인다).
- ANSI 16 의 `DarkGray`(bright black)는 일부 테마(Solarized 등)에서 배경과 가깝다. 그래서 **muted 로 표시한 정보는 모두 중요하지 않은 것**으로 제한한다. 태그, 라벨, 경로 정도이며 제목, 오류, 상태는 muted 로 그리지 않는다.
- `[L]`/`[G]` 는 색이 아니라 **글자로** 구분된다. 배지 색이 안 보여도 의미가 유지된다.

### 4.2 색 깊이 선택

| 변형 | 생성자 | 조건 |
|---|---|---|
| ANSI 16 | `Theme::ansi16()` | **기본값.** 어떤 터미널에서도 동작 |
| truecolor | `Theme::truecolor()` | `COLORTERM` 이 `truecolor` 또는 `24bit` |
| mono | `Theme::mono()` | `NO_COLOR` 가 설정됨. 모든 색을 `Reset` 으로, 스타일은 Modifier 만 사용 (`accent`=`BOLD`, `error`/`warn`=`BOLD`, `muted`=`DIM`) |

- 환경변수 판별은 `platform` 에서만 한다 (`platform::terminal::detect_color_mode(env) -> ColorMode`, `ColorMode::{Mono, Ansi16, TrueColor}`). tui 는 `ColorMode` 만 받아 `Theme::for_mode(mode)` 로 테마를 고른다 (SPEC 6절 이식성 규칙 7). 우선순위는 `NO_COLOR`(값이 비어 있지 않을 때) → `COLORTERM`(`truecolor`/`24bit`) → `Ansi16`.
- 테스트는 `Theme::ansi16()` 로 고정한다. 색 자체는 assert 하지 않고 `Buffer` 의 글자와 Modifier(`REVERSED`, `DIM`, `UNDERLINED`)를 assert 한다.

### 4.3 상태와 표시 수단

| 상태 | 글자/기호 | 스타일 |
|---|---|---|
| 선택 행 | `>` 접두 | `selection` |
| 성공 메시지 | `✓ ` 접두 | `ok` |
| 경고/안내 메시지 | `! ` 접두 | `warn` |
| 오류 메시지 | `✗ ` 접두 | `error` |
| local 배지 | `[L]` | `badge_local` |
| global 배지 | `[G]` | `badge_global` |
| 가려진 항목 | `(shadowed)` 글자 | `shadowed` (DIM) |
| 편집 중 수정됨 | `[수정됨]` 글자 | `warn` |
| 필드 포커스 | 이중 테두리 + `▶` 접두 | `border_focus` |
| 필드 검증 오류 | `✗ 메시지` | `error` |
| local 저장소 없음 | `local 없음` 글자 | `warn` |

`✓ ✗ ▶ ─ │ …` 는 유니코드 한 칸 폭 문자다. 폭 계산은 `unicode-width` 기준으로 통일한다.

## 5. 텍스트 폭 규칙 (한글)

- 자르기, 정렬, 커서 위치 계산은 모두 **표시 폭(`UnicodeWidthStr`)** 기준이다. 글자 수나 바이트가 아니다.
- 폭 2 문자가 경계에서 잘리면 그 문자를 통째로 버리고 공백 1칸을 채운다 (반쪽 글자 금지).
- 자르는 함수 하나 `truncate_to_width(s, w, ellipsis_at: End|Start) -> String` 을 `tui` 안에 두고 모든 곳에서 재사용한다. 단위 테스트 대상: `"코드 리뷰"` 를 폭 5 로 자르면 `"코드…"` (폭 5).

## 6. 상태별 화면

### 6.1 빈 목록 (저장된 prompt 없음)

목록 블록 안에 가운데 정렬 `Paragraph`, 미리보기 블록은 비움.

```
┌ 목록 (0) ───────────────────┐
│                             │
│  저장된 prompt 가 없습니다.  │
│  a 를 눌러 첫 prompt 를      │
│  추가하세요.                 │
│                             │
│  프로젝트 전용 저장소가       │
│  필요하면 터미널에서          │
│  `ph init` 을 실행하세요.    │  ← local 이 없을 때만
└─────────────────────────────┘
```

### 6.2 검색/필터 결과 없음

원인을 구분해서 안내한다. 첫 번째로 맞는 것을 표시한다.

| 조건 | 목록 영역 문구 |
|---|---|
| 필터가 `local` 이고 local 저장소 없음 | `local 저장소가 없습니다.` / `` `ph init` 으로 만들 수 있습니다. `` / `s 를 눌러 필터를 바꾸세요.` |
| 검색어 있음 | `"<검색어>" 에 해당하는 prompt 가 없습니다.` / `/ 를 눌러 Esc 로 검색을 해제하세요.` (검색어는 폭 초과 시 `…`) |
| 필터가 `local`/`global` 이고 항목 없음 | `<scope> 저장소에 prompt 가 없습니다.` / `s 를 눌러 필터를 바꾸세요.` |

### 6.3 상태 메시지 (상태바 오른쪽)

| 종류 | 접두 | 예 |
|---|---|---|
| 성공 | `✓ ` | `✓ 복사됨: 코드-리뷰`, `✓ 저장됨: [L] 코드-리뷰`, `✓ 삭제됨: [G] Code-Review` |
| 안내 | `! ` | `! 변경 없음`, `! 선택된 prompt 가 없습니다`, `! 변수 2개는 치환되지 않았습니다` (복사 시 본문에 `{{var}}` 가 있을 때 덧붙임) |
| 오류 | `✗ ` | `✗ 클립보드를 사용할 수 없습니다: <원인>` |

- 복사는 **원문 그대로**(변수 미치환) 복사한다 (SPEC 5절 확정). 변수 치환은 CLI `ph get --var` 의 몫이다 (TUI 변수 입력 팝업은 M3 이후 별도 검토).
- 클립보드 실패는 상태바 오류 한 줄만 표시한다 (SPEC 10절 확정, 대체 동작 없음).

### 6.4 오류 화면

| 종류 | 표시 |
|---|---|
| 일회성 오류 (저장 실패, 복사 실패) | 상태바 `✗` 메시지. 길어서 잘리면 `Notice` 팝업으로 전문 표시 |
| 저장소 읽기 실패 (시작 시 또는 `r`) | 목록 영역 전체를 `Notice` 형태 블록(`error` 테두리)으로 채운다: `저장소를 읽지 못했습니다` / `<원인>` / `r 다시 시도  q 종료` |
| 파싱 불가 파일 (부분 실패) | 목록에서 제외하고 나머지는 정상 표시. 상태바에 `! 읽지 못한 파일 N개` 를 표시하고, `r` 로 재로드할 때 `Notice` 팝업에 파일 경로와 원인 목록을 보여준다 |

### 6.5 로딩

저장소 접근은 동기 IO 이고 대부분 즉시 끝난다. 그래서 별도 스피너를 두지 않고, **첫 로드와 `r` 재로드 중에만** 목록 영역에 `불러오는 중…` 한 줄을 그린다(`AppState.loading: bool`). 로드가 끝나면 즉시 목록으로 교체한다. 외부 에디터 실행 중에는 TUI 가 중단되므로 화면을 그리지 않는다.

### 6.6 팝업 공통

```
        ┌ 삭제 확인 ─────────────────────────┐
        │ 이 prompt 를 삭제할까요?            │
        │                                     │
        │  [G] Code-Review                    │
        │  이 작업은 되돌릴 수 없습니다.       │
        │  local 의 같은 id 가 없으므로        │
        │  삭제 후 목록에서 사라집니다.        │
        │                                     │
        │  [y] 삭제     [n/Esc/Enter] 취소     │
        └─────────────────────────────────────┘
```

| 팝업 | 폭 x 높이 (고정) | 위젯 | 테두리 |
|---|---|---|---|
| 삭제 확인 | 50 x 9 | `Clear` + `Paragraph` in `Block::bordered` | `popup_danger` |
| 변경 폐기 확인 | 50 x 7 | 동일 | `popup_border` |
| 태그 입력 | 50 x 5 | `Clear` + `Paragraph` (입력 한 줄) + 안내 줄 | `popup_border` |
| 도움말 | 60 x 22 | `Clear` + `Paragraph` (`scroll`) | `popup_border` |
| Notice / 검증 실패 | 60 x 10 | `Clear` + `Paragraph` (wrap) | `error` 또는 `warn` |

- 위치: 화면 중앙 (`Rect` 계산: `x = (w - pw)/2`, `y = (h - ph)/2`, 정수 나눗셈).
- 삭제 팝업 본문에 **scope 배지와 제목**을 반드시 표시한다. 삭제 대상이 local 이고 같은 id 의 global 이 있으면 `삭제하면 global 의 같은 id 가 다시 보입니다.` 를 덧붙인다.
- 태그 팝업: 현재 태그를 `rust review` 처럼 공백 구분으로 미리 채운다. 쉼표와 공백 모두 구분자다. `#` 접두는 있으면 제거한다.

### 6.7 도움말 팝업 내용

3.2 ~ 3.5절의 키 표를 모드별 소제목(`탐색`, `검색`, `편집`, `팝업`)으로 나눠 그대로 보여준다. 키 표는 `keymap.rs` 의 데이터(`const KEYS: &[KeyDoc]`)에서 생성해 **도움말과 실제 동작이 어긋나지 않게** 한다.

## 7. 스크롤과 커서 규칙

- 목록: `ListState::select` + 화면 밖이면 offset 자동 조정. 위/아래 끝에서 멈춘다.
- 필터 변경으로 선택 항목이 사라지면 첫 항목을 선택한다. 같은 항목이 남아 있으면 유지한다(id + scope 로 식별).
- 삭제 후에는 같은 위치(인덱스)의 다음 항목, 없으면 이전 항목을 선택한다.
- 저장 후에는 저장된 항목(id + scope)을 선택한다.
- 하드웨어 커서: Search, TagInput, Edit 에서만 `frame.set_cursor_position` 으로 표시한다. 위치는 표시 폭 기준이다. 그 외 모드에서는 커서를 숨긴다.

## 8. 인라인 에디터 (`e` 수정, `a` 추가)

### 8.1 레이아웃

에디터는 본문 영역(상태바/키 도움말 제외)을 **전부** 차지한다. 목록/미리보기는 그리지 않는다.

```
┌ 편집: [L] 코드-리뷰-요청 ─────────────────────────────────── [수정됨] ┐
│ 저장 위치  (•) local   ( ) global            ← 새 prompt 일 때만       │
╔ ▶ Title ═══════════════════════════════════════════════════════════════╗
║ 코드 리뷰 요청_                                                         ║
╚═════════════════════════════════════════════════════════════════════════╝
┌ Tags (공백/쉼표 구분) ──────────────────────────────────────────────────┐
│ review rust                                                             │
└─────────────────────────────────────────────────────────────────────────┘
┌ Description ────────────────────────────────────────────────────────────┐
│ PR 리뷰용                                                               │
└─────────────────────────────────────────────────────────────────────────┘
┌ Body ──────────────────────────────────────────────── 줄 1/3 · 열 5 ───┐
│ 다음 diff 를 리뷰해줘. 관점: {{focus}}                                   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
 EDIT │ 필터:all │ [L] 코드-리뷰-요청                       ! 저장하지 않음
 Tab/Shift+Tab 필드  Ctrl+S 저장  Esc 취소  Ctrl+Z 되돌리기  Ctrl+Y 다시
```

| 영역 | 위젯 | Constraint |
|---|---|---|
| 바깥 프레임 | `Block::bordered` (제목: `편집: <배지> <id>` 또는 `새 prompt`, 오른쪽 `[수정됨]`) | 본문 영역 전체 |
| 안쪽 수직 | `Layout::vertical` | 수정: `[Length(3), Length(3), Length(3), Min(5)]` / 추가: 맨 앞에 `Length(1)` (scope 행) |
| Title / Tags / Description | 한 줄 입력 (`ratatui-textarea` `TextArea`, Enter 는 update 가 가로채 개행을 막는다) in `Block::bordered` | `Length(3)` |
| Body | 여러 줄 입력 (`ratatui-textarea` `TextArea`) in `Block::bordered` | `Min(5)` |
| scope 행 | `Paragraph` 한 줄 (`(•) local   ( ) global`) | `Length(1)` |

- 바깥 프레임의 안쪽(`Block::inner`)을 위 수직 레이아웃에 넘긴다.

**크기별 변형**
| 조건 | 변경 |
|---|---|
| `h < 22` | Title, Tags, Description 을 테두리 없는 `Length(1)` 한 줄 `라벨: 값` 으로 바꾼다 (`Title  : 코드 리뷰 요청`). 포커스는 라벨 앞 `▶` 와 `BOLD` 로 표시. Body 는 `Min(3)` |
| `w < 60` | 라벨은 그대로 두고 값 영역만 좁아진다 (값은 가로 스크롤). 짧은 라벨 변형은 만들지 않는다 |
| 바깥 프레임 | `w < 60` 또는 `h < 22` 이면 바깥 프레임을 생략하고 `[수정됨]` 은 상태바에 표시 |
| 최소 크기 | 2.2절의 `40x10` 미만이면 "터미널이 너무 작습니다" |

### 8.2 포커스 표시

| 상태 | 표시 (색 없이도 구분됨) |
|---|---|
| 포커스된 필드 | 테두리 `BorderType::Double`, 제목 앞 `▶ `, 테두리 `border_focus`(BOLD), 하드웨어 커서 표시 |
| 비포커스 필드 | `BorderType::Plain`, `border`(muted) |
| 검증 오류 필드 | 테두리 제목 끝에 ` ✗ <메시지>` (`error`) |
| 본문 상태 | 블록 오른쪽 제목에 `줄 <행>/<전체> · 열 <표시폭 기준>` (muted) |

포커스 순서(`Tab`): (`Scope` — 추가일 때만) → `Title` → `Tags` → `Description` → `Body` → 처음으로. `Shift+Tab` 은 역순. 초기 포커스는 수정일 때 `Body`, 추가일 때 `Title`.

### 8.3 필드 규칙

| 필드 | 입력 | 검증 (저장 시) |
|---|---|---|
| Title | 한 줄. 개행 입력 불가 | 비어 있으면 안 됨. id 규칙(SPEC 2절)의 금지 문자, 끝 `.`/공백, 예약 이름, 100바이트 초과는 오류. **수정 시에는 id 를 바꾸지 않는다** (SPEC 2절. 이름 변경은 별도 동작이며 v0.1 에 없다) |
| Tags | 한 줄. 공백 또는 쉼표 구분, `#` 접두 허용(저장 시 제거). 중복은 자동으로 합침 | 빈 태그 제거. 그 외 제한 없음 |
| Description | 한 줄. 비어 있으면 `None` | - |
| Body | 여러 줄. 줄바꿈 `Enter` | 비어 있어도 저장 가능하나 `! 본문이 비어 있습니다` 를 상태바에 표시 |

- 검증은 `Ctrl+S` 시 **`core` 의 검증 함수를 호출**해서 한다 (view 가 규칙을 복제하지 않는다). 실패하면 저장하지 않고, 첫 번째 오류 필드로 포커스를 옮기고 그 필드 제목에 `✗ 메시지` 를 표시한다. 상태바에도 `✗ Title: 사용할 수 없는 문자 ':'` 를 띄운다.
- 서비스 저장 단계의 실패(중복 id, IO 오류 등)는 `Notice` 팝업으로 표시하고 **에디터에 남는다** (입력한 내용을 잃지 않는다).

### 8.4 추가(`a`) 흐름

1. `a` → 빈 에디터. 제목 `새 prompt`. scope 행이 맨 위에 있다.
2. scope 기본값: local 저장소가 있으면 `local`, 없으면 `global` (SPEC 3.2절 규칙, `PromptService` 가 알려준 값).
3. local 저장소가 없으면 `( ) local (없음)` 으로 표시하고 선택할 수 없다. 선택 시도 시 `! local 저장소가 없습니다. ph init 으로 만드세요` 를 표시한다. 조용히 global 로 바꾸지 않는다.
4. `Ctrl+S` → 저장 → Normal 로 돌아가 새 항목을 선택하고 `✓ 저장됨: [L] <id>`.
5. id 는 title 에서 생성하며 중복이면 서비스가 suffix 를 붙인다. suffix 가 붙으면 메시지에 최종 id 를 보여준다.

### 8.5 수정(`e`) 흐름

1. `e` → 선택 항목의 값으로 채운 에디터. scope 는 고정(행 없음), 프레임 제목에 배지 표시.
2. 변경 감지: 시작 시점의 (title, tags, description, body) 스냅샷과 비교한다. 같으면 `[수정됨]` 을 숨긴다 (undo 로 원상 복구하면 다시 사라진다).
3. `Ctrl+S`: 검증 → `PromptService` 로 저장 → `updated_at` 갱신은 서비스가 한다. 변경이 없으면 저장하지 않고 `! 변경 없음` 후 Normal 로 돌아간다.
4. `Esc`:
   - 변경 없음 → 즉시 Normal.
   - 변경 있음 → 변경 폐기 확인 팝업 (8.6).

### 8.6 변경 확인 팝업

```
        ┌ 변경 사항이 있습니다 ─────────────┐
        │ 저장하지 않은 변경이 있습니다.     │
        │                                    │
        │  [s] 저장 후 닫기                  │
        │  [d] 변경 버리기                   │
        │  [c/Esc] 계속 편집                 │
        └────────────────────────────────────┘
```

- 기본 포커스(Enter)는 **계속 편집**이다.
- `s` 는 8.3 검증을 거친다. 실패하면 팝업을 닫고 오류 필드로 돌아간다.
- `d` 는 스냅샷을 버리고 Normal 로 돌아간다. 원본 파일은 건드리지 않았으므로 그대로다. 메시지 `! 변경을 버렸습니다`.

### 8.7 undo/redo 와 한글

- undo/redo 는 **포커스된 필드 단위**다 (필드를 옮겨도 다른 필드의 이력은 유지).
- 한글 IME 조합 중인 글자는 터미널이 완성 후 전달하므로 조합 상태를 다루지 않는다. 입력은 완성된 `KeyCode::Char` 로 받는다.
- 커서 열 표시와 하드웨어 커서 위치는 표시 폭 기준 (5절).
- 붙여넣기는 bracketed paste 를 활성화해 한 번의 이벤트로 받아, 여러 줄 붙여넣기가 `Enter` 로 해석되어 필드 이동을 일으키지 않게 한다 (Body 외 필드는 개행을 공백으로 바꾼다).

## 9. 외부 에디터 (`E`)

### 9.1 흐름

```
Normal ──E──▶ [사전 검사] ──▶ TUI 중단 ──▶ 에디터 실행 ──▶ TUI 복구 ──▶ 결과 처리 ──▶ Normal
                 │ 실패                                                      │ 검증 실패
                 ▼                                                           ▼
        상태바 ✗ 에디터 없음                                          Notice(다시 편집?)
```

1. **사전 검사**: `$VISUAL` → `$EDITOR` → `vi` 순으로 실행 파일을 찾는다. 모두 없으면 화면을 벗어나지 않고 상태바에 오류를 표시한다.
   `✗ 에디터를 찾을 수 없습니다. $VISUAL 또는 $EDITOR 를 설정하거나 vi 를 설치하세요`
2. **임시 파일**: 선택 항목 전체(frontmatter + body)를 임시 파일 `ph-<id>.md` 로 쓴다 (CLI `ph edit` 과 같은 `platform::editor` 사용). id 는 파일명 그대로 임시 디렉터리 안에 둔다.
3. **TUI 중단**: raw mode 해제, alternate screen 나가기. 이 동안 ph 는 화면을 그리지 않는다. 에디터에 넘기기 전에 커서를 보이게 한다. 중단 직전 상태바 메시지(`에디터 실행: vim`)는 화면에 남지 않는다(alternate screen 이 사라지므로).
4. **에디터 실행**: program 과 args 를 분리해 실행하고 종료를 기다린다. 에디터 설정에 인자가 있으면(`code --wait`) 공백으로 나눠 args 로 넘긴다.
5. **TUI 복구**: raw mode + alternate screen 재진입, 전체 화면 `clear` 후 다시 그리고, 저장소를 다시 읽는다. 선택은 (id, scope) 로 복원한다.
6. **결과 처리**:

| 결과 | 동작 | 상태바 메시지 |
|---|---|---|
| 종료 코드 0, 내용 동일 | 저장하지 않음 (`updated_at` 유지) | `! 변경 없음` |
| 종료 코드 0, 내용 변경, 검증 통과 | `PromptService` 로 저장 (`updated_at` 갱신) | `✓ 저장됨: [L] <id>` |
| 종료 코드 0, 내용 변경, **검증 실패** | 원본 보존, 임시 파일 유지 → 9.4 팝업 | (팝업) |
| 종료 코드 non-zero | 변경 반영 안 함, 임시 파일 삭제 | `✗ 에디터가 비정상 종료했습니다 (코드 <N>). 변경은 반영되지 않았습니다` |
| 시그널 종료 | 위와 동일 | `✗ 에디터가 시그널로 종료되었습니다. 변경은 반영되지 않았습니다` |
| 실행 실패 (spawn 오류) | 임시 파일 삭제 | `✗ 에디터를 실행하지 못했습니다: <원인>` |

### 9.2 중단 중에 보이는 것
ph 는 아무것도 출력하지 않는다. 에디터 화면만 보인다. 복구 후 첫 프레임에서 위 결과 메시지가 상태바에 나온다.

### 9.3 복구 안전
- 에디터 실행 중 panic 이나 오류가 나도 raw mode 와 alternate screen 이 복원되어야 한다(SPEC 5절 hook). "중단→복구" 는 RAII 가드(`SuspendGuard`)로 감싸 오류 경로에서도 복구되게 한다.
- 임시 파일은 결과 처리가 끝나면 삭제한다. 단 9.4 재편집 대기 중에는 유지한다.

### 9.4 검증 실패 팝업 (재편집 안내)

```
    ┌ ✗ 저장할 수 없습니다 ─────────────────────────────────┐
    │ frontmatter 가 올바르지 않습니다.                      │
    │                                                        │
    │   줄 3, 열 8: tags 는 문자열 배열이어야 합니다          │
    │   > tags = "review"                                    │
    │                                                        │
    │ 원본 prompt 는 변경되지 않았습니다.                     │
    │                                                        │
    │  [r/Enter] 다시 편집   [d] 변경 버리기                  │
    └────────────────────────────────────────────────────────┘
```

| 요소 | 규칙 |
|---|---|
| 제목 | `✗ 저장할 수 없습니다` (`error` 테두리) |
| 사유 | 한 줄 요약 (`frontmatter 가 올바르지 않습니다` / `id 가 올바르지 않습니다` 등) |
| 위치 | `줄 <N>, 열 <M>: <메시지>` 와 해당 줄 원문을 `> ` 접두로 인용. 위치를 알 수 없으면 생략하고 메시지만 |
| 보존 안내 | `원본 prompt 는 변경되지 않았습니다.` (항상 표시) |
| 선택 | `r`/`Enter` 다시 편집 (기본), `d` 변경 버리기. `Esc` 는 팝업 안에 `정말 버릴까요? y/n` 한 줄 확인을 띄우고 `y` 일 때만 버린다 (사용자가 입력한 내용을 잃는 경로이므로). `d` 는 바로 버린다 |

- **다시 편집**: 사용자가 저장했던 임시 파일 내용을 **그대로** 다시 연다 (원본으로 되돌리지 않는다). 파일 맨 위에 안내 주석을 넣지 않는다 (frontmatter 를 깨뜨리므로).
- 이후 흐름은 9.1 의 3~6 단계와 같다. 재편집 횟수 제한은 없다.
- **본문이 비어 있거나 title 이 비어 있는 경우**도 검증 실패로 취급한다(title). 본문 빈 값은 허용하고 `! 본문이 비어 있습니다` 만 표시한다.
- id 는 파일명이므로 임시 파일 내용에서 바뀔 수 없다. frontmatter 에 `id` 키가 있으면 무시하고 상태바에 `! id 는 변경되지 않습니다` 를 표시한다 (SPEC 2절). 이 정보는 `PromptService::save_raw` 결과의 `notes` 로 받는다.

### 9.5 `e` 와 `E` 의 관계
- `E` 는 Normal 에서만 동작한다. 인라인 에디터 안에서 외부 에디터로 넘어가는 키는 두지 않는다 (상태 복잡도 방지).
- 두 방식 모두 저장은 `PromptService` 를 통하며 검증 규칙이 같다. 차이는 외부 에디터에서만 frontmatter 전체가 노출된다는 점이다.

## 10. 미리보기 전용 모드 (`Preview`, 좁은 화면)

폭이 좁아 미리보기가 숨겨진 상태에서 `p` 를 누르면 본문 영역 전체를 미리보기가 차지한다.

- 위젯: 2.4절과 동일한 `Paragraph`. `j`/`k`/`↑`/`↓`/`Ctrl+d`/`Ctrl+u` 로 스크롤, `Esc` `p` `q` 로 목록으로 복귀.
- 상태바 모드 세그먼트는 `PREVIEW`.
- 이 모드에서 터미널이 넓어져 미리보기가 표시 가능해지면 자동으로 Normal 로 복귀한다.

## 11. TestBackend 검증 가이드

QA 가 아래 크기로 스냅샷/부분 문자열 assert 를 작성할 수 있도록 결정적으로 정의한다.

| 크기 | 기대 결과 |
|---|---|
| 120x30 | 좌 48 / 우 72, 검색 박스 3줄, 키 도움말 표시 |
| 80x24 | 좌 32 / 우 48 |
| 79x24 | 미리보기 숨김, 목록 전체 폭 |
| 80x11 | 미리보기 숨김, 검색 1줄, 키 도움말 숨김 |
| 40x10 | 최소 크기. 목록과 상태바만 |
| 39x10 또는 40x9 | "터미널이 너무 작습니다" |

검증 항목 (버퍼의 글자 또는 Modifier 로 assert):
1. 배지 `[L]`/`[G]` 가 각 행에 있다. shadowed 행에 `(shadowed)` 글자가 있고 셀에 `DIM` 이 있다.
2. 선택 행의 셀에 `REVERSED` 가 있고 행 앞에 `>` 가 있다.
3. 한글 제목이 폭 경계에서 잘릴 때 반쪽 글자가 없다 (5절).
4. 빈 목록 / 검색 결과 없음 / local 없음 문구 (6.1, 6.2).
5. 삭제 팝업에 대상 배지와 제목, `[y]` 와 취소 안내가 있고 기본 포커스가 취소다.
6. 인라인 에디터: 포커스된 필드가 `BorderType::Double` 이고 `▶` 가 있다. 변경 후 `[수정됨]` 표시, 되돌리면 사라진다. 검증 오류 시 `✗` 가 필드 제목에 있다.
7. 상태 메시지는 접두 기호(`✓ ! ✗`)로 시작한다. 다음 키 입력 후 사라진다.
8. `{{var}}` 셀에 `UNDERLINED` 가 있다.
9. 리사이즈: 80x24 → 79x24 → 80x24 순서로 그려도 선택 항목이 유지된다.

`view` 는 시계, 환경변수, 파일시스템을 읽지 않는다. 테스트는 고정된 `AppState` 를 만들어 `Terminal::new(TestBackend::new(w, h))` 에 그린다.

| # | 제안 | 결과 | 반영 위치 |

## 13. 구현 참고 (coder / architect 용)

- 파일 배치 제안: `tui/theme.rs`(토큰), `tui/keymap.rs`(키 → `Action`, 도움말 데이터), `tui/layout.rs`(순수 `compute_layout`), `tui/view/{list,preview,status,popup,editor}.rs`, `tui/text.rs`(폭 계산과 `truncate_to_width`).
